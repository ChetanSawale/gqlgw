# Benchmark

`{ posts(limit: 100) { id title <author field> { name } } }` — 100 posts by 100 distinct authors,
backend latency 0.002s per request, wrk 10s with 16 connections,
OpenResty 2 workers, 4 CPUs (x86_64), 2026-10-11.

| variant | subrequests / query | req/s | latency avg | latency p99 |
|---|---|---|---|---|
| `naiveAuthor` | 101 (then 101) | 425.73 | 47.98ms | 577.41ms |
| `author` | 2 (then 2) | 1467.53 | 10.89ms | 15.21ms |
| `cachedAuthor` | 2 (then 1) | 1851.52 | 8.64ms | 12.78ms |

Generated by `make bench` (bench/run.sh).

## Cost of the Prometheus metrics (M12)

Same query, `METRICS=1` (metrics, `log_by_lua` and upstream timing as in the configuration
generated by `gqlc render`) against no metrics: 5 alternating runs of 8 s per configuration
(2026-10-11, busy desktop machine, hence the spread). Medians:

| variant | without metrics | with metrics | difference |
|---|---|---|---|
| `author` | 1464.54 req/s | 1442.61 req/s | −1.5 % |
| `cachedAuthor` | 1925.46 req/s | 1951.19 req/s | +1.3 % |

The difference is within the measurement noise. A first version (a label string built on every
increment, 100 cache increments per request) cost 4.7 % on `cachedAuthor`: the keys are now
memoized and the cache lookups aggregated per round.
