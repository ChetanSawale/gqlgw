# Benchmark

`{ posts(limit: 100) { id title <author field> { name } } }` — 100 posts by 100 distinct authors,
backend latency 0.002s per request, wrk 10s with 16 connections,
OpenResty 2 workers, 4 CPUs (x86_64), 2026-10-11.

| variant | subrequests / query | req/s | latency avg | latency p99 |

| `naiveAuthor` | 101 (then 101) | 425.73 | 47.98ms | 577.41ms |

Generated by `make bench` (bench/run.sh).

## Coût des métriques Prometheus (M12)

Même requête, `METRICS=1` (métriques, `log_by_lua` et temps upstream comme dans la configuration
générée par `gqlc render`) contre sans métriques : 5 passes alternées de 8 s par configuration
(2026-10-11, machine de bureau chargée, d'où la dispersion). Médianes :

| variant | sans métriques | avec métriques | écart |
|---|---|---|---|
| `author` | 1464.54 req/s | 1442.61 req/s | −1,5 % |
| `cachedAuthor` | 1925.46 req/s | 1951.19 req/s | +1,3 % |

L'écart est dans le bruit de mesure. Une première version (une chaîne de labels construite à
chaque incrément, 100 incréments de cache par requête) coûtait 4,7 % sur `cachedAuthor` : les clés
sont maintenant mémorisées et les lookups de cache agrégés par round.
